## What's Next: Phase 16

### Phase 16: Message Generation & Variation
**Goal:** Generate fresh, actionable messages per intent by rephrasing intent, pulling updated index data, applying persona tone, and avoiding repetition from last 5 messages.

**Dependencies:**
- Phase 14 (index available) ✓
- Phase 15 (fresh data loaded) ✓

**Requirements to Cover:** MSG-01, MSG-02, MSG-03, MSG-04

**Success Criteria:**
1. Message generator rephrases the user intent (e.g., "You have open work on AI optimization" → "Your AI workflow could be faster — ready to tackle that?"), adds current context from index, applies persona character
2. System tracks last 5 messages per persona and detects exact phrase repeats (avoids sending identical phrasing twice in a row)
3. Generated message is actionable: nudges open topic, motivates action, or celebrates completion (not generic or passive)
4. Persona tone is consistent (e.g., AMMAR is builder-focused, HIKMAH is philosophical, TARIQ is strategic) across 5 consecutive test message generations

**Starting Point:**
- Phase 15 provides fresh or cached indices via `refresh_persona_index()`
- Index contains: topics[], completions[], activity_history[], stalled_work[], context_snapshots
- All 11 personas initialized and ready
- Public API documented in HIKMAH README.md

## Architecture Overview

### Data Flow
```
Google Drive (YAWMIYAT/sessions logs)
    ↓ [Phase 15: Refresh]
Local Index Cache (HIKMAH__knowledge_index/indices/)
    ↓ [Phase 14: Schema validation]
PersonaIndexDict (topics, completions, stalled_work, activity_history)
    ↓ [Phase 16: Generate messages]
Fresh, contextual nudges (persona-consistent tone)
    ↓ [Phase 17: Deliver]
Telegram (09:00 & 18:00 Cairo)
    ↓ [Phase 17: Track]
Response ledger (1-hour engagement window)
    ↓ [Phase 18: Adapt]
Format rotation (if <80% response rate)
    ↓ [Phase 19: Integrate]
MUNAWARA (actions), MAL (finance), TARIQ (strategy)
    ↓ [Phase 20: Validate]
Privacy audit (no raw PII, safe context tags only)
```

### Key Constraints (Non-Negotiables)
1. **Knowledge index is strict_local only** — Never egressed to Telegram/Drive
2. **Messages never include raw personal data** — Only safe context tags (e.g., "Your AI work" not "Seif's AI workflow")
3. **Sensitive topics gated by confidence <80%** — Health, family topics skipped if low confidence
4. **All refresh failures logged** — Audit trail for troubleshooting and compliance
5. **Graceful degradation** — System falls back to cached index, never silently fails

### Personas (All 11)
AMMAR, HIKMAH, TARIQ, MUNAWARA, MAL, BADAN, NAQD, SHURA, TAFRIGH, MARSAD, NIZAM

## Important Integration Points

### Phase 15 → Phase 16 Integration
**Phase 16 will use:**
```python
from HIKMAH__knowledge_index import (
    refresh_persona_index,
    load_cached_index,
    RefreshAuditLogger,
    RefreshConfig,
    load_refresh_config
)

# Before generating message:
config = load_refresh_config()  # Load from config.yaml
success, index, degradation_reason = refresh_persona_index(
    persona="AMMAR",
    drive_client=GoogleDriveClient(config.credentials_path),
    index_path=Path("HIKMAH__knowledge_index/indices/AMMAR_index.json"),
    audit_logger=RefreshAuditLogger(config.audit_ledger_path)
)

# If success: use fresh index
# If not success: index is cached, degradation_reason explains why (timeout, auth error, etc.)
```
