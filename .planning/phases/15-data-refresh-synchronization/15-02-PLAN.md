    ## Phase 15: Data Refresh Pipeline
    
    Each refresh cycle:
    1. Load refresh configuration (conversation_logs_folder, credentials_path, timeout)
    2. Initialize Google Drive client with service account credentials
    3. Query Drive for YAWMIYAT/sessions folder
    4. List and download conversation log files (JSON format)
    5. Merge new activity into per-persona indices (preserving stalled_work and completions)
    6. Log refresh attempt to REFRESH_AUDIT_LEDGER.jsonl (success or failure)
    7. On Drive unavailability: fall back to cached index, log degradation
    
    Configuration:
    - See refresh/config.yaml for externalized settings (folder paths, timeouts, credentials)
    - Operator can update Drive folder location without code changes
    
    Audit Trail:
    - REFRESH_AUDIT_LEDGER.jsonl: JSONL-formatted append-only log of all refresh attempts
    - Entry format: ts, persona, event_type, status (success/failure/partial), data_sources, files_read, error, row_hash
    - Operator can query ledger to find: "When was AMMAR index last refreshed? Why did it fail?"
    
    Failure Handling:
    - Network timeout: Fall back to cached index, log "timeout" error
    - Auth failure (401/403): Fall back to cached index, log "auth_failed" error
    - Folder not found: Fall back to cached index, log "folder_not_found" error
    - Malformed JSON: Fall back to cached index, log "json_parse_error" error
    - Schema validation error: Fall back to cached index, log "schema_validation_error" error
    
    Integration with Phase 16:
    - Phase 16 (Message Generation) calls refresh_persona_index(persona, drive_client, index_path, audit_logger)
    - Returns (success: bool, index: dict, degradation_reason: str or None)
    - Phase 16 uses returned index to extract context for message generation
    - If success=False, message generation proceeds with cached (potentially stale) index
    
    Update "Integration Points" section to include Phase 15:
    - Phase 15 (Data Refresh): Reads Google Drive logs → merges activity into indices
    
    Code example (for Phase 16 usage):
    ```python
    from HIKMAH__knowledge_index import refresh_persona_index, load_refresh_config
    
    config = load_refresh_config()  # Load from config.yaml
    drive_client = GoogleDriveClient(config.credentials_path)
    audit_logger = RefreshAuditLogger(config.audit_ledger_path)
    
    success, index, degradation_reason = refresh_persona_index(
        persona="AMMAR",
        drive_client=drive_client,
        index_path=Path("HIKMAH__knowledge_index/indices/AMMAR_index.json"),
        audit_logger=audit_logger
    )
    
    if success:
        print(f"Refreshed AMMAR index from Drive")
    else:
        print(f"Using cached AMMAR index (reason: {degradation_reason})")
    
    # Use index for message generation
    ```
