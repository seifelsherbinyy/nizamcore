# Kiro research evidence requirements

Owner: contracts/programs/KIRO_DEVELOPMENT_ENVIRONMENT.md (KDE03/05/07/08).
Phase: research phase 2. NIZAM-derived from the owner's phase-2 research and execution request.
This additive specification governs research metadata, not runtime or financial policy.

1. Preserve the phase 0-1 package and all pre-existing files. No new dependencies,
   active IDE configuration, global changes, or replacement task/verification ledger.
2. Record unique candidates, domain coverage A-Q, native/existing alternatives,
   research dispositions, evidence references and explicit next actions.
3. Retain public source URLs, retrieval times, SHA-256 snapshot identifiers and short
   exact excerpts with locators. Distinguish retrieval from detailed inspection.
4. Validate this authored metadata subset offline. Refuse malformed/unknown fields,
   duplicate identities, dangling/cross-candidate citations, missing domain coverage,
   invalid source metadata and claimed external execution or Kiro activation.
5. Validation proves internal structure only, never upstream truth, security,
   maintenance quality, raw-cache integrity, installation eligibility or activation.
6. The CLI reads only its fixed research artifact through the existing restricted
   local reader, enforces a size bound, accepts no arguments, reports fixed errors,
   and exits nonzero on invalid or unavailable input. No command execution or network.
7. Test positive and adversarial metadata, filesystem/CLI failure, and preservation;
   run the existing tooling suites and unmodified full repository harness.
8. Later installs, authenticated integration trials, upgrades and migration are separate
   approval/version-review steps. Research recommendations never grant authority.
