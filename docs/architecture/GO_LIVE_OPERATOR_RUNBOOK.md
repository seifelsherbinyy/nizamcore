### U3. OAuth client credentials (or service account)

Either route is fine; pick one.

- **OAuth client (interactive, preferred for solo).**
  1. APIs & Services → Credentials → "+ Create credentials" → OAuth client ID
  2. Application type: Desktop app
  3. Download the JSON; store at `~/.nizam/google_oauth.json`. Add path to your password manager.

- **Service account (for headless VPS).**
  1. APIs & Services → Credentials → "+ Create credentials" → Service account
  2. Grant role: `Drive File Stream User` (least privilege).
  3. Create JSON key, download, store at `~/.nizam/google_sa.json`.
  4. Share the destination Drive folder with the service account email.

Acceptance: `rclone lsd drive:` (after U4 configures rclone) lists your Drive root.

### U4. rclone-crypt passphrase + escrow

1. Install rclone locally: <https://rclone.org/downloads/>
2. `rclone config` → create remote `drive` (using U3 creds).
3. `rclone config` → create remote `drive-crypt` of type **crypt**, with:
   - `remote = drive:nizam_crypt/`
   - `filename_encryption = standard`
   - `directory_name_encryption = true`
   - `password = <random 24+ chars>` (generated by rclone, write it down)
   - `password2 = <random 24+ chars>` (rclone salt, write it down)
4. **Escrow.** Print both passphrases on paper. Store in your operator-only fire-safe. Also save
   them in your password manager. Without them the encrypted backups are unrecoverable.
5. Acceptance: `rclone ls drive-crypt:` returns no files but exits 0.

### I3. LUKS volume with AHEL separate keypair

1. Attach a Hetzner volume (e.g., 20 GB) → mount as `/srv/nizam/`.
2. `sudo cryptsetup luksFormat /dev/sdb` (Hetzner volume usually `sdb`).
3. `sudo cryptsetup luksOpen /dev/sdb nizam_strict_local`.
4. `sudo mkfs.ext4 /dev/mapper/nizam_strict_local`.
5. `sudo mkdir -p /srv/nizam/strict_local` and mount.
6. **AHEL gets its OWN volume** (`nizam_ahel`), formatted with a **distinct passphrase**. The
   passphrase is stored only in the operator's password manager, **never** alongside the strict_local
   passphrase. This enforces the AHEL separate-keypair rule.
7. Acceptance: `mount | grep nizam` shows both encrypted mounts.

### I5. systemd unit for relay

Create `/etc/systemd/system/nizam-relay.service`:

```ini
[Unit]
Description=NIZAM Phase-1 relay
After=network.target

[Service]
Type=simple
User=nizam
WorkingDirectory=/srv/nizam/strict_local/nizamcore
EnvironmentFile=/srv/nizam/strict_local/nizamcore/NIZAM__system/relay/.env
ExecStart=/srv/nizam/strict_local/nizamcore/.venv/bin/python NIZAM__system/relay/webhook.py
Restart=on-failure
RestartSec=5s

[Install]
WantedBy=multi-user.target
```

Then:

```bash
sudo systemctl daemon-reload
sudo systemctl enable nizam-relay
# do NOT start yet — see T3
```

### I6. systemd 10-min safety timer + on-append hook

Two timers:

```ini
# /etc/systemd/system/nizam-sth.service
[Unit]
Description=Publish STRATEGY_LEDGER STH
[Service]
Type=oneshot
WorkingDirectory=/srv/nizam/strict_local/nizamcore
ExecStart=/srv/nizam/strict_local/nizamcore/.venv/bin/python -m NIZAM__system.governor.strategy_sth publish
```

```ini
# /etc/systemd/system/nizam-sth.timer
[Unit]
Description=Run STH publish every 10 minutes
[Timer]
OnBootSec=2min
OnUnitActiveSec=10min
Persistent=true
[Install]
WantedBy=timers.target
```

Enable: `sudo systemctl enable --now nizam-sth.timer`.
